# 全40枚の公開手順

画像40枚の採用後に追加したカード効果・ショップ・パック・CPU・オンライン対戦を学校環境へ反映する手順です。学校のログイン情報や名簿はGitHubへ置きません。

## 1. Firebaseのルールを更新

[Realtime Databaseのルール](../firebase/database.rules.json) の全文を、Firebaseコンソールの「Realtime Database」→「ルール」に貼り替えて「公開」します。新しいルールは、対象選択、カード交換、ドローンによる確認の通信を許可します。

## 2. 学校側Apps Scriptを更新

[Code.gs](../gas/Code.gs) の全文を学校側の同名ファイルへ貼り替えて保存します。`Learning.gs` と `Bridge.html` は変更不要です。

1. 関数 `setup` を一度実行します。
2. スプレッドシートの `Cards` シートに40枚、`Packs` シートに「全カードパック」、`Decks` のサンプル・CPU候補に40枚があることを確認します。
3. Apps Scriptの「デプロイ」→「デプロイを管理」→編集→「新しいバージョン」で更新します。`/exec` のURLは従来と同じです。

`setup()` は不足しているカードとパックを追加します。所持カード、Gポイント、先生が変更した価格、既存パックの設定は消しません。

## 3. 公開サイトを更新

上の2項目が完了したら、リポジトリの `main` へ全40枚の変更を反映します。GitHub ActionsがGitHub Pagesを更新します。旧部屋の対戦は旧通信手順を使い、新しく作る部屋から40枚の効果に対応します。

## 4. 確認

- [Gカード](https://ken-ui-web.github.io/g-card/#/home) の図鑑に40枚が表示される。
- ショップに単品販売対象のカードが並び、「全カードパック」の排出率が N 60%／R 30%／SR 8.5%／SSR 1.5% と表示される。
- サンプルカードでCPU戦を行い、連続パンチ・バリア・毒矢などの効果が結果に出る。
- 管理者テスト対戦でルームを作り、対象を選ぶカードと入れ替えを1回ずつ試す。テスト対戦ではGポイントは増減しない。

学校用の設定値やパスワードをコードへ貼り付ける必要はありません。
