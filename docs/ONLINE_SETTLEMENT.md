# オンライン対戦の勝敗確定（2026-11-28）

## 生徒への扱い

| 状態 | 勝利数 | G報酬 |
| --- | --- | --- |
| 通常の決着 | 勝者に1勝 | 従来どおり |
| デッキ登録後、片方が30秒以上切断、相手は接続中 | 接続している側に不戦勝1勝 | 両者0G。ミッションも進めない |
| 両者が30秒以上中断、決着なし | 無効試合・双方加算なし | 0G |
| デッキの準備中に相手が退出 | 無効試合 | 0G |
| 決着した後に切断 | 決着した結果を維持 | 決着した結果どおり |

短い切断からの復帰は継続。再接続時は古い通信時刻を判定してから接続状態を更新し、不戦敗・無効試合の再開を防ぐ。両者が戻らない場合は勝利を付ける処理自体が走らず、復帰時に無効を確定する。

## 仕組み

- 学校ログインとFirebase匿名UIDを照合。開始時に所持カード・筋トレ・ライフを学校側で検証して非公開の開始デッキを保存する。
- 各ラウンドでスプレッドシートへ書き込まない。Firebaseの公開済みカード、選択、コミット値を、決着時に学校側の共通エンジンで再計算する。暗号化カードだけは秘密の証明を選択時に学校側へ保存する。
- 敗者の結果送信や終了操作を待たずに、片方の端末から両者の結果を確定できる。
- 通常決着を切断より優先。再送はロックと対戦IDごとの既存ログ確認で重複を防ぐ。
- Firebaseトークンは処理中の照会にだけ使い、シートやログに保存しない。Firebaseの参加者限定読み取りルールは変更しない。
- 古いクライアント同士の結果照合は互換用に残す。新しいデッキ登録済みの試合は旧方式で確定させない。公開後は両端末を更新して新しい部屋で対戦する。

## 更新・検証

`npm run build:online-engine` がブラウザーと同じソースから `gas/OnlineEngine.gs` を生成する。GASの同期SHA-256に合わせてハッシュの非同期境界だけ変換する。`npm test` と `npm run build` も先に生成する。

Apps Scriptには `Code.gs`・`Learning.gs`・`OnlineEngine.gs`・`OnlineSettlement.gs`・`Bridge.html`・既存マニフェストを配置。既存デプロイを更新する。`OnlineMatches` の追加3列は最初の利用時に追加され、名簿・カード・Gは書き換えない。

`tools/test-online-settlement.cjs` は通常決着、敗者未送信、途中の不戦勝、両者中断、準備中中断、再接続、結果再送、改ざん・UID不一致を実際のGAS関数で検証する。既存のオンライン対戦テストはGAS生成エンジンとの一致も検証する。
