# 段階7：学校用 Apps Script の更新

Gカードの学校用スプレッドシートから、これまで使っている Apps Script を開く。既存のデプロイを更新する。新しいプロジェクトは作らない。

1. `gas/Code.gs` の全文を学校用 Apps Script の `Code.gs` に貼り替えて保存する。
2. Apps Script で新しいスクリプトファイル `Learning.gs` を作り、`gas/Learning.gs` の全文を貼って保存する。既存の `Bridge.html` はそのまま使う。
3. 左側の歯車「プロジェクトの設定」→「スクリプト プロパティ」で次の2つを追加する。`REFLECTION_SOURCE_ID` は既存の授業振り返りシステムのスプレッドシートURLの `/d/` と `/edit` の間、`REFLECTION_APP_URL` は生徒用振り返りアプリの `/exec` URL。学校固有の値をGitHubには書かない。
4. エディタ上部で関数 `setup` を選んで1回実行する。初回は、Gカードシートにテスト用の列と設定項目を用意し、振り返りのポイント付与開始時刻を記録する。従来のカード・価格・名簿は上書きしない。
5. 右上の「デプロイ」→「デプロイを管理」→既存のウェブアプリの編集→「新しいバージョン」でデプロイする。実行ユーザーは「自分」、アクセスは既存設定を維持する。既存の `/exec` URL は変わらない。
6. [Gカードの管理画面](https://ken-ui-web.github.io/g-card/#/admin) を開き、「テストの作成・集計」で短いテストを1つ作る。問題の正解を設定し、公開設定を保存する。受験済みのテストの問題は変更できないため、改訂には「テストを複製」を使う。
7. 管理画面の「Gポイントと育成の数値」で `learningEnabled` を `1` にすると、生徒のホームに「テスト」「振り返り」が表示される。公開前は `0` のままにする。

## 既存の授業振り返りシステムとの関係

- 振り返りの入力・修正・先生による評価は、従来の授業振り返りアプリで続ける。Gカードは同じ学校メールを名簿に照合し、授業ごとの初回提出日時を読む。Gカード側に本文や評価はコピーしない。
- ポイントは、今回の `setup()` を初めて実行した後の初回提出に対して1授業1回だけ付与する。以前の試験的な提出記録には遡って付与しない。生徒がGカードの「振り返り」から既存アプリへ移動して提出し、戻って「提出記録を確認してGを受け取る」を押すと照合する。
- 既存アプリの授業設定にある「テストURL」欄には、Gカード管理画面に表示される「生徒向けのテストリンク」を貼れる。これで授業から該当テストへ移動できる。

## データと負荷

- 正解はサーバーに置き、生徒へ問題を配る際に含めない。回答は提出時に1回送信してサーバーで採点する。シートの `TestResponses.answersJson` は空欄で、生徒、テスト、回数、得点、満点、付与G、日時だけを残す。
- 下書きは生徒の端末の localStorage に保存する。別端末には引き継がれない。改ざんできる領域なので、得点・Gポイントの計算には使わない。
- ホームを表示するだけではテスト履歴や既存の振り返りシートを読まない。各機能を開いた時に読み、振り返りの提出メタデータは15秒キャッシュする。Gポイントの付与は提出・同期時に即時記録する。「ここまでを保存」操作は不要。
- 問題画像は、学校の閲覧権限を設定した既存のGoogleドライブ画像URLを指定する。生徒のiPadで閲覧できることを確認する。Apps Scriptからの画像アップロードはこの段階に含まれない。

## 確認

先生の学校アカウントで短いテストを受け、結果とGポイントを確認する。続けて同じテストを受け、自己ベスト相当の差額だけが付与されることを確認する。`TestResponses` の回答列が空欄で、得点列が記録されることを確認する。振り返りは新しい授業で1回提出し、Gカードで1回だけ受け取れることを確認する。35人同時の実機負荷は、この学校用デプロイ後に確認する。
