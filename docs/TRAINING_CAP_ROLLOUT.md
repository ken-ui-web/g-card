# 筋トレ上限とGポイント補償（2026年11月10日）

## 利用者への説明

カード間の強さを整えるため、グーカードの筋トレ値に上限を設ける。連続パンチは+6、てこの原理は+10、電動アシストは+15、その他のグーカードは+20。上限に達すると「筋トレ完了」と表示し、追加の費用は発生しない。

既に上限を超えていたカードは上限まで調整する。超過した回数に使ったGは全額返す。さらに、今回の変更のお詫びとして、利用者一人につき100Gを一度だけ配布する。初回アクセス時に調整内容、返還額、お詫び100Gの内訳を表示し、確認するまで通知を残す。

## 返還額

過去の筋トレ価格は変更されていない。筋トレ値を `n` から `n+1` にする価格は `20 + 2n` G。変更前の値を `L`、新しい上限を `C` とすると、返還額は `n=C` から `L-1` までの価格の合計。

例：連続パンチが+10なら+6に調整し、+6→+7から+9→+10までの `32+34+36+38=140G` を返す。保存されている筋トレ費用の累計からも140Gを引くため、そのカードを後から売却しても返還分を再度受け取れない。複数枚ある場合は所持カードごとに計算して合算する。上限以下のカードは変更しない。

## 学校アカウントでの処理

GASの `bootstrap` が初めて実行されたときに、その利用者の調整と配布を行う。名簿に登録済みの利用者は、次にGカードを開くと自動的に受け取る。既存の所持カードや設定を変えるため、Apps Scriptの新しいデプロイ版が必要。

利用者行の `trainingPolicyJson` に版、返還計画、元の残高、通知確認状態を保存する。残高の加算と計画の保存を同じ行の更新で行い、カードの値と `PointLog` を更新してから完了印を付ける。通信が途中で切れた場合は計画を再開し、100Gと返還額を再加算しない。`PointLog` には `training_policy_bonus` と `training_cap_refund` を版番号で一度だけ残す。通知確認は `ackTrainingPolicy` で別に記録する。

通常のログインボーナスやミッション報酬は別枠。今回のお詫びを受け取っても、それらの受け取り回数に影響しない。GASは上限超過の筋トレ要求を費用計算前に拒否し、同じカードが複数行の要求に分かれていても合計回数を判定する。

## ゲストでの処理

端末内の `g-card-guest-v1` を初めて読み込む際、同じ上限調整と100G配布を一度だけ行う。ゲストの記録と通知確認はその端末のローカルストレージに保存する。別端末のゲスト記録とは合算されず、端末のデータを消すと記録も消える。

## 確認項目

- 上限超過のカードについて、筋トレ値・返還額・残高・売却額が一致する。
- 再読み込みや同時期の再接続で、100Gと返還額が二重にならない。
- 上限ちょうどのカードでは筋トレボタンが無効になり、直接APIに送った要求も拒否される。
- 通知の確認後に再表示されず、未確認なら次のアクセスでも表示される。
- 学校アカウントとゲストの両方で動作する。
