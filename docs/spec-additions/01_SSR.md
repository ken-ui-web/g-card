## 1. 背景（なぜ変更するのか）

オーナーが試作で遊んだところ、次の問題が見つかった。

- 残り2枚になったとき、お互いの手の種類の組み合わせが同じ（例：グー・チョキ 対 グー・チョキ）だと、あいこになるか、1回ずつ勝ち合うだけになり、**実質的に何も起こらない**。

対策として、**最もレア度の高い「SSR」のカードだけは、あいこでも効果が発動する**ルールを加える。SSRのカードは裏面が光っていて、相手にもSSRだとわかる。相手は「SSRに勝つ手」を出さないとSSRの効果を止められないため、あいこが安全ではなくなり、読み合いに緊張感が生まれる。

## 3. 詳細仕様

### 3-1. レア度の名前の変更（UR → SSR）

| 変更前 | 変更後 |
|---|---|
| N／R／SR／UR | **N／R／SR／SSR** |

- 内部の値も `UR` を `SSR` に変更する（カードマスタの `rarity`、パックの排出率、売却額、画像ファイル名など、すべて）。
- 排出率・売却額などの数値は変えない（UR の値をそのまま SSR に引き継ぐ）。
  - 排出率【仮】：N 60%／R 30%／SR 8.5%／**SSR 1.5%**
  - 売却額【仮】：N 10／R 30／SR 100／**SSR 300**
  - 天井：「SR以上確定」のまま（SSRも含む）
- 枠のデザイン（虹色ホログラム枠＋キラキラ）も、そのまま SSR の枠とする。

### 3-2. あいこのときのSSRの効果発動

**ルール**
- じゃんけんの結果ごとに、効果が発動するかどうかは次のとおり。

| 自分のカード | 勝ち | あいこ | 負け |
|---|---|---|---|
| N・R・SR | 発動する | **発動しない** | 発動しない |
| **SSR** | 発動する | **発動する** | 発動しない |

- 片方だけがSSRのあいこ：**SSRの効果だけ**が発動する。
- **両方ともSSRのあいこ：両方の効果が発動する。**
- 「効果なし」状態（封印・ベアハッグ）のSSRは、あいこでも勝っても発動しない。
- 「AI」の効果（負けたらあいこ扱い）で負けがあいこに変わった場合も**あいことして扱う**。そのため、相手か自分のカードがSSRなら、そのSSRの効果は発動する。
- あいこで発動した効果に「対象を選ぶ」ものがある場合（例：相手のカードの種類を変える）、そのSSRの持ち主が対象を選ぶ。

**両方ともSSRのあいこのときの解決順**
1. **ライフが少ないプレイヤーのSSRの効果から先に**解決する。ライフが同じなら、シード乱数で決める（オンライン対戦で両方の端末の結果を一致させるため）。
2. 続けて、もう一方のSSRの効果を解決する。
3. **KO判定は、両方の効果を解決し終わってから行う。** 両方ともライフが0以下になった場合は引き分け。

**ラウンドの解決順序（SPEC.md 6-5）の変更**

```
4. カード効果の解決
   - 勝敗がついた場合：勝者のカードの効果を解決する（従来どおり）。
     ※負けた側のカードは、SSRであっても発動しない。
   - あいこの場合：
       ・どちらもSSRでない → 何も起きない（従来どおり）
       ・片方だけSSR     → SSRの効果だけを解決する
       ・両方SSR         → 上の「両方ともSSRのあいこのときの解決順」で解決する
   - 「効果なし」状態のカードは、どの場合も発動しない。
（5以降は従来どおり。KO判定は手順4の効果をすべて解決したあとに行う）
```

### 3-3. デッキに入れられるSSRは1枚まで

- デッキを組むとき、**SSRのカードは1枚まで**しか選べない。
- デッキ選択画面では、SSRを1枚選んだ時点で、ほかのSSRのカードを暗く表示して選べないようにし、「SSRはデッキに1枚までです」と表示する。
- **サンプルカードセット、CPUデッキ**もこのルールに従う。管理者画面のデッキ管理で、SSRを2枚以上入れて保存しようとしたらエラーにする。
- オンライン対戦でも、デッキ確定時に相手側の端末でこのルールを確認し、違反していたら無効試合とする。
- バトル中の「入れ替え」の効果で、手札のSSRが2枚以上になるのは**問題ない**（デッキを組むときだけのルール）。

### 3-4. SSRの裏面の演出（相手にもSSRだとわかる）

- SSRのカードは、**裏面も虹色にキラキラ光る**。自分の手札でも相手の手札でも同じように光る。
- 相手には「種類」と「SSRであること」がわかる。カードの名前や効果はわからない（従来どおり）。
- 光の表現：
  - 裏面の画像の上に、**SSR用の光る縁取り画像**（下記3-6）を重ね、さらに虹色の光が流れるCSSアニメーションを重ねる。
  - 種類の色（黄・青・緑）とアイコンは、光っていても見分けられること。
- 効果でカードの種類が変わっても（手品など）、SSRの光はそのまま残る。
- 「ジャイアントスイング」の効果で手札が裏向き・シャッフルされた場合も、SSRの光はそのまま見える。
- 動きを減らす設定（iPadの「視差効果を減らす」）がオンの場合は、アニメーションを弱めた静止画の光にする。

### 3-5. あいこでSSRが発動するときの演出

- あいこの演出のあと、SSRのカードが強く光り、「**SSR発動！**」の特別な演出を入れてから効果を発動する。
- 両方ともSSRのあいこでは、「**SSR同時発動！**」の演出を入れ、解決順に沿って1枚ずつ効果を見せる。
- 演出はこれまでどおりタップでスキップできる。

### 3-6. 画像の追加・変更

| 部品 | ファイル | 生成サイズ | 透過 | 題材（たたき台） | 生成する段階 |

### 3-7. SSRのカード候補と数値の見直し

- これまでURだった候補カードは、すべてSSRになる。

| ID | 名前 | 種類 |
|---|---|---|
| G015 | ジャイアントスイング | グー |
| G016 | 伝説の拳 | グー |
| C014 | レーザーカッター | チョキ |
| C015 | ロボットアーム | チョキ |
| P014 | プログラミング | パー |
| P015 | ハッキング | パー |
| P016 | AI | パー |

- **あいこでも発動するようになるため、効果が強くなりすぎるおそれがある。** 段階4でSSRのカードを追加するとき、オーナーと一緒に数値を見直すこと（例：レーザーカッター80ダメージ、伝説の拳の「筋トレ効果2倍」など）。Codexは、追加するときに調整案を提案してよい。

### 3-8. 試作での確認（段階3〜4）

- バトルエンジンには、SSRのルール（3-2）と、デッキのSSR制限（3-3）を実装し、単体テストを書く。テストする内容：
  - SSRが勝ち → 発動／SSRがあいこ → 発動／SSRが負け → 発動しない
  - 片方だけSSRのあいこ → SSRだけ発動
  - 両方SSRのあいこ → 両方発動。ライフが少ないほうが先に解決。KO判定は両方の解決後（同時にライフ0なら引き分け）
  - 「効果なし」のSSR → 発動しない
  - AIの効果で負けがあいこに変わった場合 → SSRの効果は発動する
  - デッキにSSRを2枚入れようとすると拒否される
- 初期4枚にはSSRがないため、**試作用の調整画面（`/#/dev/tuning`）に「仮のSSRカードを使う」スイッチを追加する**（初期値はOFF）。
  - ONにすると、仮のSSRカード1枚（例：レーザーカッター（チョキ・SSR・仮の数値））が、プレイヤーとCPUのデッキ選択に出てくる。
  - オーナーがSSRのルールを実際に遊んで試すためのもの。生徒向けの画面には出さない。
  - 仮のSSRカードの画像は、ダミー画像でよい（画像は段階4でチェックを受けてから生成する）。

## 5. 採用しなかった案（記録）

- **あいこボーナス**（あいこのたびに追加ダメージがたまり、次に勝った人が受け取る）：採用しない。あいこで何かが起きるのはSSRだけ、というルールにして、SSRの特別感を大切にするため。
- パワー比べ（あいこのときに攻撃力を比べる）、あいこでしょ（あいこのカードを手札に戻して選び直す）：採用しない。
