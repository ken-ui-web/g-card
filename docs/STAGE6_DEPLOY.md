# 段階6：Gポイントとカード育成の更新手順

段階5で使っている学校のスプレッドシートとApps Scriptをそのまま使います。新しいアカウントやシートは不要です。名簿や学校の設定値はGitHubへ送らず、学校側に残します。

**段階6をすでに導入した後の修正更新**では、下の手順の2と4を行ってください。`setup` は再実行不要です。購入・筋トレの完了表示と、同日ログインボーナスの重複防止が反映されます。現在のGポイントと過去の `PointLog` は自動で変更しません。

## 学校側のApps Scriptを更新する

1. 学校アカウントでGカード用スプレッドシートを開き、**拡張機能 → Apps Script** を開きます。
2. `コード.gs` の全文を、このリポジトリの [`gas/Code.gs`](../gas/Code.gs) の全文に置き換えて保存します。`Bridge.html` は変更しません。
3. 関数の選択欄で `setup` を選び、**実行**します。既存の学校ドメイン、管理者メール、名簿、所持カード、Gポイントは残したまま、価格などの設定行と初期パック・デッキ・ミッションが追加されます。
4. **デプロイ → デプロイを管理 → 現在のウェブアプリの編集（鉛筆） → バージョン「新しいバージョン」 → デプロイ** を選びます。既存の `/exec` URLを引き続き使います。エディタで保存しただけでは公開中のウェブアプリは更新されません。

## 公開ページで確認する

1. iPadのホーム画面からGカードを開き、ホームに「カード購入」「トレーニング」「デッキ・図鑑」が表示されるか確認します。古い画面が出る場合は一度アプリを閉じて開き直します。
2. 管理者ページの「カードとゲームの設定」で、価格・報酬・販売設定・パック・ミッション・サンプル／CPUデッキを確認します。`生徒にGポイント機能を公開` は初期値 **0（停止）** です。先生のアカウントでは停止中も試せます。
3. 先生のアカウントで購入・筋トレ・CPU対戦を試す場合、実際にGポイントやカードが学校のシートへ記録されます。`Users`、`OwnedCards`、`PointLog`、`BattleLog` の値を確認します。
4. 同じ操作を連打した場合も、画面に出る残高とシートの `Users.gPoint` が一致するか確認します。
5. 生徒にも使ってもらう段階になったら、管理者ページで `生徒にGポイント機能を公開` を **1** にして保存します。生徒はアプリを開き直すと新しいメニューを使えます。

初期パックは、画像が完成しているN・Rの５枚のみを収録した「スタートパック」です。３枚200G、N 70%・R 30%で、天井はありません。SR・URカードが完成したら、管理者画面で排出率と収録カードを設定して別のパックを追加できます。排出率は購入画面に表示され、抽選はGAS側で行われます。

段階6のコードと自動テストを用意済みです。**GASの更新が終わるまで、公開ページでは新しい機能を「準備中」と表示します。** 更新後も、管理者が公開スイッチを入れるまでは生徒に表示しません。
